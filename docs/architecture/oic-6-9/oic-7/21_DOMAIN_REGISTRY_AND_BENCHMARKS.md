# OIC-7 v1.0 — evaluation domain and benchmark registry

**Owner:** OIC Evaluation Fabric. It measures resolved OIC targets; it does not own runtime provider credentials or product business data. A benchmark is a governed protocol and case population, not a leaderboard row. Scope is OIC-internal or application/tenant restricted; all content has rights/sensitivity and provenance. Identifiers are UUIDs; published revisions and content manifests are immutable. See [baseline](../../oic-6-8/oic-7/20_OIC7_EVALUATION_AND_EVOLUTION.md).

## Minimal hierarchy

`EvaluationDomain` is a controlled taxonomy label and plugin key, not one table per domain. `BenchmarkPackRevision` is a signed manifest combining domain, task types, dataset revisions, optional environment revisions, suite revisions, execution/sampling/repetition policy, metric/judge revisions, aggregation/gates and OIC-6 budget ceiling. `DatasetRevision` contains immutable ordered `(caseRevisionId, weight, slice labels, content hash)` entries. `CaseRevision` owns a task input, oracle/rubric reference, rights, difficulty metadata, answer exposure tier and source lineage. `EnvironmentRevision` pins simulator/container/fixture/tool state when execution needs one. `SuiteRevision` selects pack cases/conditions and measurement policy. `Campaign` groups target runs on one released suite; `Run` pins one target fingerprint, seed/repetition policy and budget; `Attempt` is one physical execution; `Measurement`, `Report`, `Comparison` and `PromotionVerdict` follow. Avoid separate Scenario/Task entities in v1: `CaseRevision` contains scenario and task type. Introduce a Scenario family only if shared multi-case state later demands identity. `BenchmarkRelease` pins pack revision and effective/public/private tier with changelog; never edit a published release.

Registry publication validates case hashes, no duplicate IDs/content near-duplicates beyond declared repetitions, rights, scope, oracle availability, environment compatibility, slice coverage, budgets and evaluator version. A published pack is frozen. Retire by status/reason/new release reference; historical reports remain interpretable. Live/rotating benchmark creates new release revisions and comparability breaks unless a bridge study on common anchor cases validates linking. Imported external benchmarks use adapter version, upstream license, source checksum, transform map, permitted uses and revocation handling; an adapter cannot claim native OIC authorship. No raw external answers enter general logs.

## Domain taxonomy and initial packs

Taxonomy permits `reasoning`, `mathematics`, `coding`, `agentic_coding`, `software_engineering`, `terminal_computer`, `data_analysis`, `tool_function`, `retrieval_RAG`, `memory`, `knowledge`, `language_multilingual`, `Arabic`, `customer_service`, `sales`, `negotiation`, `safety_reliability`, `efficiency`. Packs may have multiple tags, but a primary domain and explicit subtask/method. Initial required **architecture** packs are deterministic coding/tool/schema, retrieval/memory, multilingual/Arabic, and communication/sales simulations; implementation rolls out only after oracle and rights gates. Public practice, private validation and sealed promotion holdout are separate tiers with distinct ACL. Production-shadow cases require per-tenant authorization, minimized/redacted artifacts and no automatic promotion to shared benchmarks.

## Case quality and contamination

Each case pins source, author/generator, creation and review time, content hash, answer/oracle hash, task family, difficulty evidence, applicable policies, language/script, safe prompt/output limits and expected capability slice. Difficulty is an empirical property of a reference cohort/revision, not an author guess. Registry quality checks: oracle determinism or judge rubric clarity, adversarial validity, ambiguity review, language parity, source rights, contamination scan, safety and case retirement reasons. Generated cases are **quarantined drafts** with generator model/prompt/seed revision, novelty/dedup evidence and independent oracle verification; a generator never certifies its own answer. `BenchmarkCompiler` is a deterministic publish validator producing manifest hash and validation report, not an autonomous test author. It rejects leak paths, missing rights, incompatible environment or incomplete slice metadata.

Protected holdouts use separate encryption keys/ACL and answer access only in evaluator workers. Candidate generator, OIC-8 and normal operator report APIs receive aggregate/safe error categories. Access logs and export decisions are retained; suspected exposure marks release `COMPROMISED`, blocks promotion and triggers replacement. Practice examples are not used as sealed holdout. To prevent repeated tuning on a holdout, limit attempts per candidate lineage, rotate releases and reserve a final unseen cohort. Dedup across public/private/live releases uses privacy-preserving hashes where lawful; false negative contamination remains a stated risk.

**Lifecycle:** `DRAFT→VALIDATED→PUBLISHED→RETIRED|COMPROMISED`; immutable after published. **Commands:** create revision, validate, publish, retire/compromise, import adapter, request restricted export; all require dataset-admin permission, scope, idempotency and audit with manifest digest. **Queries:** bounded registry/pack/release/case metadata, never protected answers by default; content requires separate ACL. **Indexes:** domain/tier/status/scope, `(packId, revision)`, manifest hash unique, case source hash, release date. **UI:** canonical registry, coverage/slice/rights inspector, tier and status labels; no fake quality rating. **Tests:** unchanged manifest on replay, rights conflicts, duplicate/leak detection, holdout ACL, release comparability and case retirement. **Rollout:** internal fixture pack → reviewed private packs → sealed holdout after security review.
