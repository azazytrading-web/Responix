# OIC-8 v1.0 — proposal factory, learning firewall and validation bridge

**Owner:** OIC governed learning service. It may read authorized OIC execution/OIC-6/OIC-7 evidence, create scoped proposals and request candidate/evaluation work. It has no permission to mutate production bindings, security grants, provider credentials, pricing, quota, audit, evaluator definitions, protected holdouts, or Core Memory/Knowledge directly. All entities have UUID, app/tenant scope, source evidence IDs, policy revision, actor, timestamps and immutable published revisions.

`SignalRevision` normalizes source observation, cohort, time window, exposure denominator, missingness, bias/censoring and deduplication key. Aggregation groups *compatible* signals by task/scope/revision; a spike without denominator or adverse evidence cannot become a conclusion. `HypothesisRevision` states falsifiable mechanism, predicted direction, counterevidence and affected slices. `ProposalRevision` pins hypothesis, target class/current revision, one bounded diff, predicted multi-objective impact, source graph, generator identity, budget and approval level. `LearningPolicyRevision` is a target allowlist, allowed delta, OIC-6 budget, concurrent experiment cap, data class ACL, critical slices, OIC-7 suite/holdout policy, review roles and canary ceiling. Negative evidence and rejected proposals remain retained and visible, preventing repeated failed suggestions. `LearningMemory` is an internal catalog of hypotheses/outcomes with provenance, not production OIC Core Memory and not a self-write into user memory.

**Eligibility and dedup:** a signal is eligible only when source type/ID/revision and same-scope authorization resolve, observation window and denominator are known, evidence is not revoked/contaminated, privacy policy permits this purpose, and source freshness meets `LearningPolicyRevision`. Grouping key is `(scope, targetFingerprint, task/cohort, sourceMethodRevision, window, policyRevision)`; exact source IDs dedupe, but distinct contrary events remain. Aggregation records included/excluded IDs and reasons, selection bias, uncertainty and coverage; a `NO_SIGNAL` window is not a positive signal. A proposal command atomically creates one immutable `CandidateRevision` from a published parent+diff digest only after policy/rights/budget checks; duplicate key returns same candidate. It cannot apply that diff to production.

Target registry V1 permits profile settings within existing validation bounds, instructions/specification, scoped binding among authorized variants, and revisioned retrieval/context/tool policies only where a real OIC owner exists. Unsupported targets are rejected rather than invented. Candidate generation is offline-first, on redacted aggregate evidence and public practice cases. It receives no sealed holdout answers, private tenant content beyond consent, credentials or evaluator source. Generated candidate is an immutable OIC-7 `CandidateRevision`; OIC-8 does not create an active model revision in place. The dataset firewall checks source lineage, protected-answer access logs, practice/holdout overlap, generator prompt inputs and tenant rights before evaluation. Violation quarantines candidate and records incident. OIC-7 executes independent validation with campaign OIC-6 budget; OIC-8 only receives report/verdict aggregate. No proposal reaches reviewable status from a local heuristic score.

**Evaluator-only firewall:** no OIC-8 service identity has decryption, query, export or job permission for protected answer artifacts. `RequestEvaluation(candidateId, suiteRevisionId, learningPolicyRevisionId, budgetId)` passes references only to OIC-7; the evaluator resolves protected cases inside its own enclave and returns only approved report/verdict fields. OIC-8 may not query per-case hidden answers through error text, traces, logs, Memory, Knowledge or ordinary runtime. Dataset exposure registry is checked before and after run. Any confirmed/suspected breach quarantines proposal, invalidates verdict for promotion and preserves incident evidence.

Multi-objective search has preregistered primary objective and hard guardrails across quality, safety, privacy, latency, provider cost, OIU and critical language/task slices. It may generate a bounded finite candidate set under explicit search budget, never unlimited optimization or hidden holdout feedback. No auto-promotion. Promotion levels are `NONPRODUCTION`, `SHADOW`, `CANARY`, `BROADER` with human approval at every production transition initially; the OIC-7 promotion command owns pointer writes. Online observation after canary is monitoring only: a failed guardrail suspends expansion and triggers reviewed rollback, not self-healing mutation. Online learning and automatic approval are future business/security activation decisions. Missing monitoring yields `UNVERIFIED` and freezes rollout.

State machine: `OBSERVED→TRIAGED→HYPOTHESIZED→PROPOSED→CANDIDATE_CREATED→EVALUATING→REVIEWABLE→APPROVED→CANARY→VERIFIED|ROLLED_BACK`; `REJECTED|QUARANTINED|EXPIRED|INCONCLUSIVE` can terminate at relevant gates. State transitions are idempotent and append audit/evidence edge in same transaction. A stale target revision, incomplete source, exceeded budget, compromised holdout, denied scope or OIC-7 inconclusive verdict blocks. Worker crashes are recovered via fenced DB work; duplicate signals dedupe by source+window+policy; duplicate proposal generation has unique parent+policy+digest. A reviewer cannot approve their own high-risk proposal or modify evaluation rules after results. All Console controls use frozen canonical Interface/Instrumentation, with clear source evidence, diff, counterevidence, budget, gate and rollback. Queries are scope-filtered/cursor-bounded; no raw tenant or holdout content in generic report.

**Exact mutation gate:** OIC-8 has no production-binding write credential or command. An authorized human invokes OIC-7 `Promote(candidateId, verdictDigest, expectedBindingVersion, rolloutPolicyRevision, idempotencyKey)` after fresh `decisionEligible=true`, `PASS`, settled OIC-6 budget and rollback target readback. OIC-7 alone commits the binding CAS and decision audit. Canary remains unverified until predeclared quality/safety/cost/latency slices and observation coverage pass. `UNVERIFIED` blocks expansion; severe regression triggers alert and an authorized OIC-7 rollback command, never silent self-mutation. Online autonomous learning is disabled by default.

**Test invariants:** OIC-8 has no binding/credential/grant write path; protected answer unreachable by generator; negative evidence immutable; bounded candidate count and spend; stale report blocks; critical slice regression blocks; missing OIC-6 cost does not become free; promotion needs OIC-7 PASS plus human approval; rollback preserves prior pointer. **Rollout:** review-only signal registry, then offline proposals, then nonproduction evaluation, then owner-gated canary and monitored rollback. No runtime implementation is authorized by this document.
