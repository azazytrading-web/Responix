## OIU identity

`OiuValue` is the shared treatment for actual OIU amounts: a fixed `◈ OIU` mark, tabular numeric glyphs, amber OIC accent, accessible high-contrast styling, an isolated LTR number for RTL layouts, and localized Unknown text. It is used by economics assessments, admission budgets/balances/capacity instruments, and the evaluation run accounting drill-down. Provider USD, tokens, percentages, record counts and timestamps retain their own units and visual treatment.

## Counter closure findings

- No counter was removed or hidden because its source was unavailable.
- Counters sourced from paged endpoints are labeled as page counts/latest-page evidence; empty pages do not claim an unbounded total.
- Unimplemented or unavailable values remain visible with the view's existing `UNMEASURED`, `UNKNOWN`, `UNAVAILABLE`, dormant, or explicit empty state.
- The Evaluation Command Center's prior `LOCAL FIXTURE ONLY` default was incorrect for this implementation. It now displays the server-returned provider connection state, run execution state, worker readiness, and configured adapters without implying that configuration alone caused a dispatch.
- Run-level DeepSeek usage/cost/OIU drill-down reads only persisted OIC records. It does not reprice, calculate OIU, manufacture dispatches, or coerce missing values to zero.

## Remaining source limitations

Some Console workspaces intentionally expose bounded list pages rather than global rollups. This audit records that scope in the UI. A future all-time aggregate should be added as a canonical API projection only if product acceptance requires it; the Console must not infer one by adding unrelated pages.

## Final evaluation-accounting readback

The scoped Packet 7.6 readback is consistent across four actual DeepSeek provider attempts: 376 input tokens, 310 output tokens, assessed provider cost USD 0.00030945, and 686 OIU consumed. OIC-6 reserved 2,048 OIU and released 1,362 unused OIU; each admission is `SETTLED`, and run-level settlement is accepted only when reserve equals consume plus release. The run inspector reads these totals from canonical provider-usage and OIC-6 ledger rows. Unknown usage, cost, or settlement remains unknown rather than zero. This readback introduced no provider dispatch.
