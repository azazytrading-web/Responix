# OIC-7 — reproducible evaluation, measured DNA and controlled evolution

> **HISTORICAL / DIRECTIONAL PREDECESSOR - NOT ACTIVE IMPLEMENTATION AUTHORITY.** The owner-approved OIC-6 through OIC-9 v1.0 lock in [the canonical OIC-6 to OIC-9 architecture](../../oic-6-9/00_MASTER_ARCHITECTURE_LOCK_MANIFEST.md) supersedes this material for implementation. Retained for historical context; do not use to override the locked package.


## Evaluation objects and identity

`DatasetRevision` is an immutable manifest of `CaseRevision` IDs plus content hashes, rights/sensitivity and provenance; cases contain versioned input, reference/rubric and allowed disclosure. `SuiteRevision` pins dataset revision, case selection/slices, metric revisions, judge revisions, target constraints, sample policy and budget. `Campaign` groups comparisons; `Run` pins one suite and target fingerprint; `CaseAttempt` records provider attempt, execution/trace, output artifact reference and status. `Measurement` is immutable per case/metric/judge revision with availability, polarity, unit, confidence and provenance. `AggregateReport` pins measurement IDs, algorithm revision, slice and missingness. `Comparison` pins baseline/candidate reports and comparability verdict. `PromotionVerdict` is a signed/hashed immutable gate result, not a promotion. New identifiers are UUIDs; immutable revisions cannot be edited after use.

Evaluated target identity is the full resolved tuple: model edition/revision/variant, runtime binding+scope/environment, provider connection, upstream model, profile revision, instruction/specification digest, execution parameters, tool/retrieval/Memory/Knowledge policy revisions where relevant, and transport/adapter version. The execution fingerprint hashes canonical sorted payload plus suite/dataset/case/metric/judge revisions, evaluator code version, seed if supported, requested provider model identifier and safety settings. Provider behavior may remain nondeterministic; report reproducibility as `DETERMINISTIC`, `CONFIGURATION_REPLAYABLE`, `BEST_EFFORT`, `NONDETERMINISTIC`, or `INSUFFICIENT_PROVENANCE`. Same fingerprint permits cache reuse only with identical content and policy rights; it does not promise identical provider output.

## Bounded engine and integrity

PostgreSQL durable work items use unique `(runId, caseRevisionId, attemptOrdinal)` and leases/fencing; stages `QUEUED → RESERVED → RUNNING → CAPTURED → SCORED → COMPLETE`, with terminal `FAILED|CANCELLED|INCONCLUSIVE`. A retry resumes durable state and never duplicates a logical Measurement; a provider call can repeat after ambiguous timeout, so each physical attempt is separately metered and evidenced. Case input/output artifact is encrypted, access controlled and retention bound; generic trace/audit holds only allowlisted summaries. Each case obtains OIC-6 admission before outbound provider work, with campaign budget and rate limits. No admission means `BUDGET_BLOCKED`, never a zero score. Worker crash/DB outage leaves lease for fenced recovery; provider timeout is ambiguous until attempt reconciliation. Cancellation stops future dispatch and releases safe holds, while already dispatched usage remains accountable.

Deterministic metrics (exact/schema/tool-contract checks) are preferred where valid. Reference metrics state their reference revision. Operational metrics (latency, error, usage, cost) are separate from quality. Human ratings use blind randomized assignments, rubric revision, reviewer identity and disagreement adjudication. Model judges pin judge model/configuration/prompt/rubric revision, use blinded randomized candidate order, calibration controls, self-preference checks and repeated judgments; evaluator is not assumed ground truth. Pairwise and absolute scores are distinct types. Judge drift creates new revision/calibration finding; historic values remain labeled and cannot be silently compared across judge revisions. Metric definitions include type, direction (`HIGH_IS_GOOD`, `HIGH_IS_BAD`, `TARGET_RANGE`), valid range/unit, normalization revision and missing-data policy. Composite scores require explicit weights, guardrails and missingness rule; no universal intelligence score.

Aggregate only comparable case cohorts and metric/judge revisions. Report eligible/attempted/completed/missing counts, per-slice results, paired differences where the same cases were run, confidence interval or bootstrap method revision, effect size, variance and minimum practical difference. Predeclare alpha and multiple-comparison correction for promotion claims; no significance from tiny samples. An inconclusive interval, missing protected slice or asymmetric failures blocks promotion. Baseline and candidate have the same suite/dataset revision and comparable fingerprint dimensions except declared treatment. Pareto tradeoffs show quality/cost/latency/safety separately; expensive evaluation is budgeted in OIC-6. Never present a changed cohort or judge revision as a simple winner.

Holdout answers are sealed behind separate evaluator permission; candidate generation and OIC-8 only see aggregate verdict and bounded error categories. Dataset lineage and content hashes detect mutation and duplication. Contamination controls include train/eval overlap detection where provenance permits, access logs, embargoed cases, rotated hidden holdouts and invalidation of exposed cohorts. A compromised holdout produces `CONTAMINATED`, blocks gates and requires new revision; historical reports are not erased.

## Model DNA and evolution

`DnaTraitDefinitionRevision` registers 13 X1 display dimensions with exact metric sources, polarity, context (task/domain/cohort/provider), aggregation, minimum sample, freshness and uncertainty thresholds. `DnaMeasurement` references report/metric IDs and definition revision; values are measured only when all gates pass. `UNMEASURED`, `INSUFFICIENT_SAMPLE`, `STALE`, `UNSUPPORTED`, `CONTAMINATED` and `MEASURED` are distinct. Profile configuration values never become DNA measurements. The UI table is primary; radar polygons include only comparable measured traits, show missing gaps and context/uncertainty, and cannot connect fabricated zeros. Context-dependent trait values are not universal model properties.

`CandidateRevision` is immutable and records parent model/profile/binding revisions, author, change diff, target scope and rationale. Champion/challenger is adopted **per application/tenant/environment binding**, not as a global model rank. A candidate progresses `DRAFT → EVALUATING → REVIEWABLE → APPROVED → PROMOTED` or `REJECTED|EXPIRED`; approval requires matching immutable reports, holdout/safety/regression gates, OIC-6 budget reconciliation, scope authorization and expected current binding revision. OIC-7 has **no automatic production promotion**. A privileged command compare-and-swaps the scoped binding, records previous binding and audit, then readback verifies. Failure leaves prior binding. Rollback is a new guarded command to a known prior revision, not deletion of history. Post-promotion monitoring may trigger a reviewed rollback. No direct model weight training is implied.

## API, UI and rollout

API families: revisioned datasets/cases/suites/metrics/judges, campaigns/runs/case status, reports/comparisons, DNA measurements, candidates/verdicts and promotion commands. Every read/write is scope checked, idempotent where retried, and exposes evidence IDs/availability rather than hidden content. Console consumes frozen Interface/Instrumentation libraries for run state, comparison, slice/uncertainty, candidate lineage and inspector evidence; no placeholder scores. Rollout: deterministic evaluation against synthetic internal fixtures, then restricted real provider cohorts with OIC-6 metering, then calibrated human/model judging, then DNA traits one by one, then gated candidates. Promotion remains separately owner-approved.
