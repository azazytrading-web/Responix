# OIC-7.2 execution failure matrix

This is the implementation check record for packet 7.2. The locked architecture in `docs/architecture/oic-6-9/oic-7/23_SCHEDULER_EVIDENCE_AND_BUDGETS.md` remains authoritative. Failure evidence never becomes a target-quality score. Run status is finalized only after every planned case reaches a terminal state.

## Implementation evidence

- The rollback-only PostgreSQL fixtures cover physical retry identity, unresolved and settled admissions, exact OIC-6 settlement legs, release of measured unused reservation, no-admission release, `BUDGET_BLOCKED` without provider attempt, expired-lease `INCONCLUSIVE`, immediate provider-outcome ambiguity projection, invalid-environment projection, cancellation, outbox replay/recovery, and sealed-oracle verification.
- The API worker classifies failures after a provider response separately from sandbox preflight. These post-response failures are not on the safe provider retry allowlist.
- Retry requires a published terminal event, no artifact/evidence on prior attempts, a terminal and reconciled admission for every attempt, an active hard OIC-6 policy, and renewed campaign capacity. It preserves the logical case/repetition and creates a new physical attempt.
- Claims now rotate across application/tenant scope heads, enforce one active evaluator work lease across replicas, and apply the configured minimum dispatch interval per provider connection using OIC-6 provider-attempt timestamps. A rate-limited job remains queued and receives no admission or attempt.
- Latest isolated Docker runs passed the sandbox adapter 12/12 and executable worker integration 5/5; a prior combined 17/17 run also passed. All runs use the existing locked policy; no sandbox control was relaxed.
