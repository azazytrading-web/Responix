# OIC-7 v1.0 — metrics, judges, statistics and comparability

## Typed measurement

`MetricDefinitionRevision` pins method code/version, domain, construct, unit, value type (`BOOLEAN|COUNT|DECIMAL|CATEGORY|PAIRWISE`), valid range, polarity (`HIGH_IS_GOOD|HIGH_IS_BAD|TARGET_RANGE`), normalization (if any), source/oracle requirement, missingness/failure policy, aggregation rule and criticality. `Measurement` stores raw value (or no value), availability (`MEASURED|INSUFFICIENT|UNSUPPORTED|INVALID|STALE|REDACTED`), attempt IDs, metric/judge revision, source artifact digest, scope, occurred/evaluated times and evidence quality. Objective oracle results outrank subjective judges for factual state; a model judge cannot turn a failed security test into pass. Value 0 exists only with `MEASURED`. Quality, operational reliability, safety, latency, OIU and cost are separate dimensions. Composite metrics require published weights, scale, guardrails and missingness policy and cannot override critical failure; no universal score is required in v1.

**Normative metric revision schema:** `id`, `revision`, `type`, `unit`, `polarity`, `applicableTargetClasses`, `applicableDomains`, `rangeOrCategories`, `missingSemantics`, `oracleOrJudgeRevisionId`, `aggregationMethodRevision`, `uncertaintyMethodRevision`, `minimumEffectiveN`, `criticality`, `normalizationRevisionOrNone`, `sourceArtifactRequirement`, `publishedDigest`. Publication fails if a field is unspecified or type/range/polarity conflict. A changed method creates a new revision. A metric can be measured while its report remains decision-ineligible under the [formal protocol](26_EVALUATION_PROTOCOL_AND_COMPARABILITY.md).

`JudgeRevision` pins model/provider, prompt/rubric, calibration set, output schema, decoding parameters, language, position-randomization seed policy and code digest. Judge workers receive blind candidate labels and no identities that bias preference; pair order is randomized/counterbalanced and recorded. Absolute ratings and pairwise preferences are different measurement types. Judge ensemble is **optional**: publish aggregation and disagreement policy before running; majority is not assumed calibrated. Human evaluation uses blinded reviewer assignment, training/calibration, conflict-of-interest exclusion, rubric revision and adjudication; agreement (e.g. percent, kappa where applicable) and missing ratings are reported, not concealed. Judge drift is checked on anchor cases; a drifted revision becomes `SUSPENDED` for new promotion verdicts, old reports retain original meaning. Self-preference, verbosity, position, language and provider bias get separate calibration slices. Model judge cannot view protected answer outside evaluator ACL.

Judge type is `RULE|REFERENCE|HUMAN|MODEL|ENSEMBLE`. `RULE` executes deterministic assertions, `REFERENCE` compares against a pinned answer/rubric, `HUMAN` uses calibrated blinded reviewers, `MODEL` uses pinned model/prompt, and `ENSEMBLE` combines published member revisions by explicit rule. Every judge can return `ABSTAIN` with reason; abstention is missing coverage, not a zero or a tie. Disagreement is stored per member/reviewer and can trigger adjudication; a consensus score never erases it. Calibration reports specify anchor cohort, language/slice, error rate, inter-rater agreement where meaningful and expiry. Drift beyond published threshold suspends new decision use; no retroactive rewriting.

## Trial and statistical plan

Suite revision preregisters population, primary/secondary metrics, slices, trial/seed count, comparator, minimum n/effective n, practical effect threshold, alpha or confidence level, multiplicity family, missingness handling and stopping rule. A *capability* estimate describes performance under specified conditions; *reliability* reports frequency/variance across repeated trials and failures. Difficulty is calibrated to reference cohort and release, not a universal label. Repeated trials retain all attempts and physical cost; one lucky run cannot be selected post hoc. Report within-case trial variance and between-case variance. No score normalization to 0–100 unless a trait definition validates a mapping; raw unit remains primary.

For matched case IDs and aligned conditions, compute paired differences with stratified bootstrap confidence interval (resample cases, then trials within case; fixed algorithm/seed revision), plus sample count, effect size and practical threshold. For binary paired outcomes use an appropriate paired method recorded in analysis revision. For unpaired cohorts, report descriptive results but default promotion verdict `NOT_COMPARABLE`. Small sample or wide interval yields `INCONCLUSIVE`. If many candidates/metrics/slices are tested, predeclare family and use Holm correction or simultaneous intervals; exploratory analyses are labeled exploratory and cannot silently become gate evidence. Critical slices (safety, privacy, Arabic, high-risk tenant/task) require independent non-regression thresholds and minimum evidence; aggregate wins cannot cancel a critical regression. Missing hard cases count in coverage and, under a predeclared conservative policy, may fail gate; excluding them after seeing outcome is forbidden.

**Comparable-result contract:** same benchmark release/dataset/case set (or validated bridge), environment revision, metric/judge revision, sampling/stopping policy, artifact rights and declared target treatment. Provider/model revision, routing, profile and parameters are target dimensions; differing dimensions are acceptable only if explicitly part of treatment. Report `FULL`, `PARTIAL`, `DESCRIPTIVE_ONLY` or `INCOMPARABLE` with reasons. `PARTIAL` can display common-case estimates and coverage but cannot drive production promotion unless a separately published gate explicitly permits a common-case cohort with minimum coverage and critical slices. A newer benchmark release is a new cohort; leaderboard entries never silently compare across releases. Calibration drift suspends affected judge comparisons until bridge study. Published result correction creates a new report/regrade lineage with reason and original retained.

**Pareto and economics:** compare quality, safety, latency, OIU and cost on common cases with evidence status. A target dominates another only if no worse on every required measured dimension within declared tolerance and better on at least one, with uncertainty considered. Unknown cost prevents a cost frontier claim. Cost-per-success denominator is measured successes on eligible cases; numerator includes all attempts and judging overhead as specified, with coverage and invoice/estimate status. OIU-per-success remains separate. No implicit monetary conversion, no single business value score.

**API/UI:** report response includes release/target/analysis revisions, as-of, n/coverage, missing reasons, interval/method, slices, critical gate status, cost evidence level and evidence graph links. Canonical Interface tables/Inspectors display raw and normalized values with unit; Instrument gauges only when scale/direction is valid. Pairwise view names baseline/candidate after blinded evaluation completes. **Tests:** hand-computable fixture cases, shuffled order, small n, optional stopping, multiple comparisons, missing hard slice, old judge, changed release, cost unknown, asymmetric failure, category misuse and CI deterministic seed. **Operations:** calibration drift, low coverage, invalid oracles and report staleness alert; no automatic winner from a leaderboard.
