# OIC-9 — operational resilience and certification

**Status:** OIC-9 architecture scope owner-approved on 2026-10-11: production hardening, resilience, certification and final operational closure. Implementation remains NOT STARTED. Numerical SLO/RPO/RTO and capacity targets remain later activation decisions. OIC-9 does not own domain truth or replace OIC-6 admission, OIC-7 evaluation or OIC-8 governance.

## SLO and failure domains

Define service level indicators from real observations: authorized invocation availability, time to first/complete response by mode, admission latency and correctness, durable posting lag, evaluation queue age/completion, promotion decision/readback latency and recovery, audit delivery, and tenant isolation violations. Each SLO has population, exclusions, numerator/denominator, observation window, data source, error budget and owner. No target numbers are invented before owner/business approval. Report dependency readiness separately from process liveness; no fake CPU/telemetry. Failure domains: API process, DB/transaction pool, provider, worker/queue, artifact store, network/DNS, key/secret service, Console/BFF, and application/tenant scope. A provider outage is not a reason to bypass quota or call an unapproved provider.

Use bounded retries with jitter and deadlines, per-provider circuit breakers, per-tenant fair queues, concurrency ceilings, request/queue limits and load shedding. Admission and promotion fail closed on DB uncertainty; read-only reports may show stale with timestamp. A circuit breaker opens on measured provider failure, half-opens with bounded probes, never silently changes binding/price. Protect quota hot rows with fair rate limits; do not use eventually consistent Redis as hard-quota truth. Backpressure returns explicit retryable status/correlation, not unbounded queueing. Evaluate overload under mixed tenant traffic and preserve minimum audit/accounting capacity.

## Disaster recovery and integrity

Back up OIC DB, encrypted artifact metadata/content and key references with verified consistency point; test restore in isolated environment with no production dispatch. RPO/RTO are owner-approved targets measured by drills, not invented here. Restore sequence: freeze outbound dispatch/promotions, restore DB and artifact manifest, verify schema/migration version, audit tail, ledger posting/projection checksum, reservation/attempt state, evaluation leases, report/artifact hashes, DNA provenance and promotion pointer/decision history; reconcile external provider charges after restore before reopening hard quota. If DB and async state diverge, DB/outbox is authority; replay idempotently with fence. Missing evidence leaves `UNCERTAIN` and denies unsafe admission/promotion. Never replay a provider call merely because a restored job is pending.

Integrity certification jobs check model/profile revision DAG and FK scope, immutable publication hashes, usage/economic journal chains and projection rebuild, active reservations versus attempts, evaluation report→measurements→artifacts, DNA→report linkage, promotion decision→binding pointer, audit actor/request references and holdout access logs. Check outputs are signed/digested operator evidence with `PASS|FAIL|INCOMPLETE` and remediation ticket; they do not repair history silently. Migrations use expand→backfill→verify→cutover→contract, with versioned compatibility, dual-read or dual-write only when reconciliation is proven, explicit rollback point and no destructive contract until restore proof. Partial migration keeps old path; no unbounded startup migration.

## Certification and operations

Load tests measure expected steady throughput; stress finds saturation; soak finds leaks/drift; spike tests burst behavior. Include runtime latency breakdown (policy, context, retrieval, provider, verification, accounting), quota hot rows, ledger volume, evaluation campaign fairness, artifact/evidence queries, cancellation and promotion latency. Chaos exercises worker death after provider dispatch, DB rollback, provider timeout, cache/Redis loss (if introduced), network partition, judge crash, artifact loss, backup restore and promotion acknowledgement loss. Every scenario asserts no unmetered paid call, no cross-tenant data, no fabricated measurement, no unsafe promotion and recoverable audit.

Security hardening refreshes threat model and permission matrix, credential rotation/revocation, secret/dependency scans, pinned lockfile, SBOM/dependency inventory, reproducible build/artifact provenance, SSRF/egress boundaries, sandbox escape tests, protected dataset controls, rate abuse defense and tenant isolation. Reuse existing CI/deployment mechanism; do not replace it without evidence. Release candidate requires migration gate, health/readiness, scoped smoke, canary, readback, rollback drill and post-deploy verification. Operator runbooks required for unknown usage, quota drift, provider outage, stuck evaluation lease, holdout leak, wrong promotion, backup restore, credential leak and partial migration. Incident record links operational events, trace, audit, metrics and evidence IDs without overloading one table or exposing protected content.

**Final certification matrix:** architecture/version compatibility; auth/tenancy; runtime/protocol; economics/quotas; evaluation integrity/holdouts/DNA; learning governance; data integrity; resilience/DR; performance; security/supply chain; deployment/rollback; operations/runbooks; EN/AR and RTL accessibility. Each cell has test artifact, environment, owner, timestamp, status and exception approval. A critical failure or incomplete restore/holdout test means NO-GO. OIC-9 can certify only measured evidence, never self-declare operational excellence.

## Normative release certification artifact and gate

`OicReleaseCertification` has UUID, release candidate git/artifact digest, schema/migration version, deployed environment/scope, certification protocol revision, start/completion timestamps, evaluator/operator identities, requirement rows, evidence digests/locations, exception/waiver references, final verdict and signing/approval event. `CertificationRequirementRevision` pins control ID, criticality (`BLOCKING|NONBLOCKING`), exact test method, environment, freshness horizon, evidence type and applicable scope. A `CertificationResult` is immutable for a run and is exactly `PASS|FAIL|PARTIAL|NOT_EVALUATED|WAIVED`. `PASS` requires positive evidence from the pinned method and compatible release/environment within freshness horizon. Missing/expired/incompatible evidence is `NOT_EVALUATED`, never PASS. `PARTIAL` records measured subset and missing denominator, not a pass. `FAIL` records violated threshold and evidence. `WAIVED` requires named authorized approver different from executor, written reason, control/scope, compensating control, expiry/review date, risk owner and audit; blocking security/tenant isolation, hard-quota integrity, protected-holdout isolation, restore integrity and promotion-gate controls are **nonwaivable**. An expired waiver reverts the gate to `NOT_EVALUATED` until retested. Certification is immutable after finalization; re-run produces a new artifact and supersession link.

Release gate algorithm: verify candidate digests and migration compatibility; evaluate every applicable requirement; reject if any blocking `FAIL|PARTIAL|NOT_EVALUATED`, any invalid waiver, absent restore/rollback drill or integrity mismatch; require authorized release approver and audit; only then emit `CERTIFIED_FOR_SCOPE` with explicit scope and expiry. A nonblocking waived item remains visible and cannot make the matrix all-PASS. Certification does not assert numerical SLO/RPO/RTO achievement until owner-approved targets and measured drills exist; before activation these controls are `NOT_APPLICABLE_BY_POLICY` with documented decision, **not** PASS. Post-deploy readback verifies digest, readiness, ledger/job integrity and rollback path; mismatch revokes certification for that deployment and opens incident.

Failure-injection matrix pins injected fault, start/stop time, scope, expected invariant, evidence and recovery: provider completes then worker dies pre-accounting; DB reservation rollback; duplicate callback; ambiguous provider timeout; judge crash; cache loss; artifact unavailable; protected answer appears in log; promotion acknowledgement lost; backup restored with divergent work state; partial migration; overloaded quota bucket. A restore is certified only after isolated restore, schema/artifact/key consistency, ledger projection rebuild, unresolved attempt liability accounting, evaluation lease fencing, report/DNA/provenance checks, promotion pointer audit and measured RPO/RTO. Rollback certification verifies prior artifact/schema compatibility, preserved journals/evidence, restored binding pointer by authorized CAS and no hidden provider replay. Load/stress/soak and security results are separate requirement rows with actual sample/window and uncertainty; a single smoke request is not a capacity claim.
