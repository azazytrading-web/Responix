# Packet 7.6 amendment: evidence regrade and evaluation basis bridge

**Status:** Owner-directed architecture design, 2026-10-16. Parent metric revision 2, grading-only EPM, and the cohort-scoped raw-output bridge are published; the Parent replay is complete. Candidate dispatch remains blocked by the frozen minimum-sample decision gate. This amendment is limited to replaying retained OIC-controlled execution evidence for the Packet 7.6 Parent under a corrected grading basis. It does not activate the general normalized bridges or adaptive methods reserved for Packet 7.7.

## Decision and current basis

Target execution and grading are separate operations. An OIC-controlled `CaseExecution` may supply its retained output to a new grading pass without invoking the target again. The source run, attempt, admission, EPM, measurement, and report stay unchanged. The new pass creates separate measurements and a new report with an explicit source-execution link, corrected grading EPM, bridge revision, method provenance, and replay label. This is a new evaluation claim, never a correction in place or a claim that the old report was complete.

The current Parent report `0428b5c1-85c7-4360-b290-85c4424064cb` is `INCOMPLETE`; its EPM pins `oic7-objective-exact-match@1`. That metric has `BOOLEAN`, `HIGH_IS_GOOD`, `SEALED_OBJECTIVE_ORACLE`, one-trial aggregation, and minimum effective n of one, but lacks `methodRevision`, `oracleOrJudgeRevisionId`, `rangeOrCategories`, and `normalizationRevisionOrNone`. Its lower-case unit and prose missingness declaration also differ from the current typed publication contract. The source EPM and case pin `REFERENCE_EXACT_BYTES_V1`, and the sealed verifier operates on retained output and oracle artifacts. These facts make replay technically possible; they do **not** prove that revision 1 and a future revision 2 have equivalent metric semantics. The bridge status is **CONDITIONAL** until the exact revision-2 definition, code/method digests, alias mappings, and validation evidence are independently reviewed and published. The bridge never assigns a value to revision 1 or changes its `UNSUPPORTED`/missing result.

The existing EPM remains the immutable record of how a target was executed. The corrected Parent grading EPM describes the same Parent execution dimensions plus the new grading method and cites the source run as replay-only evidence. A separate Candidate execution EPM uses the same corrected grading basis and declares the single Candidate treatment. Both are published before Candidate dispatch. A report therefore displays **both** its execution EPM and effective grading EPM; no source run FK is rewritten.

## EPM dimension split and comparison rule

- **Execution dimensions:** resolved target/binding/provider identity, declared instruction or other treatment, generation parameters, input assembly/harness, retry, attempt and OIC-6 budget policy, and output limits. Preserve the actual resolved tuple and request hash. A changed output limit, truncation behavior, harness, or hidden treatment is a potential confound, even when grading is identical.
- **Grading dimensions:** metric and judge revisions, oracle method/code, thresholds, unit and normalization, missingness/abstention/failure rules, aggregation, uncertainty and statistical method.
- **Shared conditioning dimensions:** application/tenant scope, rights, release/dataset/suite, ordered case/trial schedule and source hashes, environment and action/observation semantics, exposure tier, holdout validity and verification tier. Any dimension affecting input or interpretation must match or be an explicitly validated bridge field.

The bridge validates transfer of **raw output evidence** from the historical execution EPM into the corrected Parent grading EPM. It does not translate a revision-1 score. Comparison may be `DIRECTLY_COMPARABLE` on the two **effective grading EPMs** only when their grading and shared dimensions match exactly, their execution dimensions match except the preregistered single Candidate treatment, and the Parent's source-to-grading bridge is published, unrevoked, cohort-specific and verified. The comparison retains both execution EPMs and bridge ID/digest and labels the Parent `REGRADED_FROM_RETAINED_OUTPUT`. A differing grading field without such a bridge remains `DESCRIPTIVE_ONLY`; invalid source rights, artifact or release make it `NOT_COMPARABLE`. A general cross-release, cross-oracle or numerical normalized comparison is outside this amendment.

`COMPLETE`, `DIRECTLY_COMPARABLE`, `decisionEligible`, and a promotion `PASS` are separate claims. Decision eligibility additionally requires a **prepublished** gate policy for this cohort, adequate effective n and critical slices, paired uncertainty and multiplicity handling, settled OIC-6 usage/cost coverage, fresh holdout and verified evidence. The current comparison and verdict code hard-codes `decisionEligible=false`/`INCONCLUSIVE`; implementation must replace this with evidence-backed gate evaluation without allowing a caller flag to bypass it. One matched case can support a descriptive comparison and an honest `INCONCLUSIVE`; it cannot be called promotion-ready merely because the suite minimum is one. If the preregistered gate cannot make this exact one-case design decision-eligible, the paid Candidate dispatch stays blocked.

## Bridge validation and replay

1. Publish a corrected metric revision through distinct author/publisher actors. Compare every revision-1 field with revision 2. Preserve the Boolean exact-byte construct, polarity, eligible target/domain, criticality, aggregation, uncertainty, minimum n, sealed-oracle source and missing/failure behavior. Record and independently validate any unit or missingness aliases and all newly explicit fields. Confirm `REFERENCE_EXACT_BYTES_V1` against source EPM, case and verifier code digests; no undefined legacy score is translated. A semantic change, unverifiable alias, changed oracle behavior, judge behavior, threshold, normalization, case interpretation, language rule or protected-data policy makes this bridge `REJECTED`.
2. Publish the corrected Parent grading EPM, Candidate execution EPM, bridge and decision gate **before** the unused Candidate dispatch. Freeze the Parent source case set and Candidate treatment. Do not tune the method, benchmark or gate after observing Candidate output.
3. An authorized server-side regrade command accepts scoped source case execution IDs, corrected grading EPM and bridge IDs, and an idempotency key. It verifies a terminal OIC-controlled attempt, durable admission and settlement, exact release/case/target identity, output manifest and SHA-256 digest, artifact status/key version, oracle reference/digest, source EPM and bridge scope. Reuse the sealed verifier and Vault capability; it must not accept caller-supplied output or oracle bytes. Missing artifacts result in `UNGRADABLE`; mismatches result in `INVALID` plus integrity evidence, never a guessed score.
4. Run evaluator logic only. Persist new typed measurement and report in an idempotent transaction with a replay-specific outbox event. The regrade worker has no runtime/provider executor or admission capability. Assert no new provider attempt, physical attempt, OIC-6 admission or reservation. Record safe audit events for draft, validation, publication, replay, report and comparison with IDs/digests and actors only. No browser response includes protected output, oracle, hidden tests, secrets or reviewer material.
5. Reconcile the new Parent report as `COMPLETE` and `OIC_EXECUTED_VERIFIED` only if every source and grading completeness check passes. Retain the old `INCOMPLETE` report verbatim. A bridge or complete report alone does not establish decision eligibility.

Roll out with additive schema and replay writes disabled until migration, scoped readback and integrity checks pass. Rollback disables new bridge publication and replay work while retaining every bridge, pass, report, audit and outbox record already written; it never rewrites source evidence.
