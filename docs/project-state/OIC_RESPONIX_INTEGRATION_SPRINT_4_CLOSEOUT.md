## Locked architecture

OIC is internal Oi infrastructure. Responix is its first consumer and retains workspace membership, Agents, conversations, messages, Memory, Knowledge/RAG, tools, CRM data, channels, human handoff, workflows, Guard, queues, scheduling, channel serialization, and outbound delivery. Customers do not receive OIC credentials or direct OIC access.

OIC and Responix run as separate processes with separate persistence ownership and communicate through HTTP/API contracts. Existing Agents default to `LEGACY`; explicit `OIC` Agents use an Oi Model identity without requiring a Responix Provider Runtime snapshot. OIC results continue through Responix Guard and outbound ownership. No direct cross-database import or read/write was introduced.

## Database migration incident

The first local deploy of `000045_oic_agent_runtime_decoupling` failed because `migration.sql` contained a UTF-8 BOM. No database side effects occurred. The failed attempt was marked rolled back with `prisma migrate resolve`; the BOM was removed and the migration was reapplied successfully. Final schema and data verification passed. The historical `ROLLED_BACK` migration record is valid and was preserved. The pre-OIC-4 recovery backup remains intact. No migration was rerun during this acceptance.

## Local credential handling

The recovered OIC platform credential remains in ignored `.env.oic.local`. The two RESPONIX machine credentials are in the ignored Responix `.env`, where the connector reads them. Credential values, selectors, database passwords, and provider secrets are not included in this document or Git.

The ignored Responix `.env` has an invalid placeholder AI encryption key. For local service startup only, the unified smoke used a random process-only key; it was not written to disk and no provider credential was read or changed.
