# OIC-8 — evidence-driven controlled improvement

> **HISTORICAL / DIRECTIONAL PREDECESSOR - NOT ACTIVE IMPLEMENTATION AUTHORITY.** The owner-approved OIC-6 through OIC-9 v1.0 lock in [the canonical OIC-6 to OIC-9 architecture](../../oic-6-9/00_MASTER_ARCHITECTURE_LOCK_MANIFEST.md) supersedes this material for implementation. Retained for historical context; do not use to override the locked package.


**Boundary:** learning means proposing bounded changes to existing OIC configuration from observed evidence, then testing through OIC-7. It does not mean model weight training, hidden reasoning collection, self-granted access, direct production mutation, automatic Memory/Knowledge rewriting, or bypass of evaluation.

## Objects and pipeline

`LearningSignal` references immutable source evidence (execution, OIC-6 accounting, OIC-7 report, human feedback) and carries scope, observed window, selection bias/availability, redaction class and deduplication key. A signal is an observation, not a conclusion. `HypothesisRevision` states a falsifiable mechanism, target cohort, predicted direction and counterevidence. `ProposalRevision` pins a hypothesis, parent target revision, one bounded diff, expected impact, risk class, budget, owner and evaluation plan. `Experiment` pins candidate revision, OIC-7 suite and OIC-6 budget; `DecisionRecord` pins immutable gate report, reviewers, authorization, expected production pointer and rollout. A rejected result and contrary evidence stay append-only.

Allowed initial target classes: intelligence profile revision settings within existing validated bounds, model revision instructions/specification, model binding routing among already authorized variants, and reviewed retrieval/verification policies. Each change creates a new existing-domain revision or a candidate revision; it never edits an active revision. Security grants, machine/provider credentials, plan/quota/pricing rules, audit policy, holdout definitions, evaluator/judge rules and product boundary are **prohibited targets**. Memory and Knowledge may produce a suggested reviewed draft in their existing governance workflows; no direct self-write, self-activation or source-authority upgrade. New learning target classes require separate architecture/security approval.

Pipeline: collect scoped signal → deduplicate and assess provenance → register hypothesis/counterevidence → human triage → generate one bounded immutable candidate → obtain OIC-6 budget/admission → OIC-7 evaluate on public development set plus sealed holdout → require quality, safety, latency and cost guardrails with uncertainty → human approve → scoped canary compare-and-swap promotion through OIC-7 command → post-promotion verification → expand, pause or rollback. At every stage a stale target revision, missing evidence, budget exhaustion, failed authorization, contaminated holdout or incomplete report blocks forward progress. OIC-8 only requests candidate creation/evaluation and consumes signed verdicts; it never owns the production binding write.

## Governance and recovery

`LearningPolicyRevision` defines target allowlist, max diff, scope, cohort, OIC-6 cost ceiling, concurrent experiments, rate, minimum sample, protected slices, approval roles, canary fraction/window and rollback trigger. Human approval is mandatory initially. No auto-promotion; future auto-approval is a separate business/security decision with new acceptance. Candidate generator gets only permitted source summaries and unprotected development evidence, never holdout answers or credentials. Proposal explanation links every claim to source IDs and states uncertainties/counterevidence. Audit each access, proposal transition, approval, promotion, expansion and rollback with actor and policy revision.

Blast radius is bounded by application/tenant, binding/environment and canary traffic fraction; no cross-tenant implicit rollout. Promotion uses expected binding revision and durable decision record in one transaction, followed by readback. If interrupted before commit, prior state remains; if committed but acknowledgement lost, retry reads decision and pointer rather than writes again. Rollback is a new authorized compare-and-swap to retained prior revision and does not erase evidence. Verify post-promotion with predeclared online guardrails and observation window; lack of telemetry yields `UNVERIFIED`, not success. Severe safety regression freezes expansion and alerts reviewer. Drift opens a new signal; it does not self-adjust production.

Operations track signal backlog, rejected hypotheses, evaluation budget, report expiry, canary cohort, guardrail breaches, unverified promotions and rollback readiness. UI uses canonical X1 controls to show source chain, diff, evaluation verdict, scope, approval and rollback; no fake uplift or live-learning claim. Rollout begins review-only signals and proposals, then bounded nonproduction experiments, then operator-controlled canary with explicit rollback drill. OIC-8 cannot start until OIC-7 evaluation and promotion gates are accepted.
