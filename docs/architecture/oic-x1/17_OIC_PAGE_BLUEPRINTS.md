# OIC Console Page Blueprints

Page-specific actions inherit shared [command/draft state](22_OIC_ACTION_COMMAND_EVENT_ARCHITECTURE.md), [permission states](23_OIC_PERMISSION_AWARE_OPERATOR_UX.md), [failure/recovery](24_OIC_FAILURE_RECOVERY_AND_ROLLBACK.md), and [live/freshness semantics](21_OIC_LIVE_STATE_AND_TEMPORAL_ARCHITECTURE.md). Blueprints below specify domain purpose and evidence; they do not create per-page mutation models or imply a live event source.

**Status:** target architecture. Names map current client `View` state to workspaces, not current URL routes. Common requirements for every row: distinguish empty/loading/error/unavailable; actions are server-confirmed; technical inspector is allowlisted and secret-safe; all metrics include real source/unit/freshness; EN/AR + LTR/RTL desktop/narrow; OIC-7 evaluation is **PLANNED** unless a row says no dependency. An empty-state message must not hide a failed request.

## Detailed implementation contracts

The `CURRENT BACKEND SOURCE` is the source-of-truth for available fields/actions, not a promise that all appear in the current UI. In all subsections below, filters/search/sort options must be supported by an API query or applied to a bounded complete response; do not imply server-side filtering if only client sorting exists. Empty means successful zero-result; loading retains workspace identity; error means request failed; unavailable means required source could not answer. `Future OIC-7` is explicitly a dependency only where stated.

### Overview

- **Purpose / operator question:** Is the OIC control and intelligence platform responding, and where should I investigate? **Current structure:** snapshot hero/count cards, readiness and recent application/audit data; **problems:** counts can be mistaken for telemetry and visible density can imply unmeasured precision. **Target:** COMMAND / Flight Deck.
- **Default / entities / navigation:** grouped System Core first; then model, provider, factory, lab, cognitive activity and operations. Entities are only those in metric instances. Local nav is section anchors; inspector is metric source/entity; drawer on narrow. No wizard.
- **Actions:** primary refresh/open selected workspace; secondary choose time range only when history exists, focus/compare only when supported. Filters scope/time only if API query honors them; sort by product priority/currentness; search entities via scoped picker.
- **Metrics:** current health and snapshot counts; execution fields per trace only; future rates/resources only with source, denominator, unit and history. Empty snapshot is valid; loading shows grouped skeleton; API error shows retry; unavailable metric remains labeled unavailable; live has source timestamp and no implied stream.
- **Lifecycle / feedback / insight:** no lifecycle controls. Refresh shows source time/failure. Insights classify fact/derivation/warning/recommendation/prediction/unknown and link source. Technical inspector shows metric key/version/formula/scope/source/freshness, never secret metadata.
- **Layout/localization/source:** desktop grouped grids with progressive disclosure; narrow collapsible sections/list cards; EN labels and Arabic reviewed labels, RTL composition with LTR numeric/time semantics. Source `console-snapshot.controller.ts`, `health.controller.ts`, BFF `api/console/route.ts`; future OIC-7 only measured evaluation panels. Acceptance: every cell traces to source and drilldown; unavailable vs zero tested.

### Applications

- **Purpose / operator question:** Which OIC client applications exist and what identity/model visibility belongs to each? **Current:** create form and application/tenant/principal snapshot rows; **problems:** weak relationship navigation. **Target:** FOUNDATION / Applications; local nav Inventory, Access, Visibility.
- **Default/entities:** inventory sorted by stable key/name; OicApplication plus actual related counts. Inspector has application identity/status/time and linked tenants, principals, model visibility. Drawer narrow; wizard only if later multi-step application onboarding exists.
- **Actions:** create app; secondary open tenant/principal/model views. Filters lifecycle/status; sort key/name/created time when provided; search key/display name. No unsupported edit/delete action.
- **Metrics/states:** records and related counts only. Empty/loading/error/unavailable follow common rules; successful create shows returned ID/key and audit/correlation if supplied; lifecycle only transitions supported by API.
- **Inspector/localization/source:** app ID/key and safe status; no credentials. Desktop table plus inspector; narrow labeled records; EN/AR, RTL with keys/IDs LTR. Source `identity/foundation.controller.ts`, `foundation.service.ts`, snapshot. OIC-7 no direct dependency. Acceptance: created app linked and scoped operations remain app-bound.

### Tenants

- **Default/entities:** app-scoped tenant list; OicTenant and active external references. Inspector shows app, references, principal tenant grants. Tenant drawer narrow; no wizard unless reference onboarding spans validated steps.
- **Actions:** create tenant; add/revoke/remap external reference where endpoint supports. Secondary open principals/grants. Filters application/lifecycle/reference source; sorting display/key; search tenant key/name/external reference. Scope selector is application picker.
- **Metrics/states:** reference/grant counts from records only. Empty tenant set, loading, failed query and API unavailable distinguished; reference change feedback includes server response. Lifecycle transitions only API-backed.
- **Technical/localization/source:** tenant/app IDs, sourceType/externalId with LTR. Desktop split list/inspector; narrow record drawer. Arabic strings for reference terminology, RTL layout. Source `identity/foundation.controller.ts` and service. No OIC-7. Acceptance: cannot remap across application and revoked references no longer appear as active.

### Service Principals

- **Actions:** grant/revoke scope, grant/revoke tenant, issue/revoke credentials only through API. Secondary inspect audit and app. Filter application/status/scope; sort key and recent activity; search key/name. Pickers list allowed scope vocabulary and active tenants.
- **Metrics/states:** credential status/expiry and actual lastUsedAt only; no usage rate unless source. Empty/loading/error/unavailable distinct; issued credential is one-time display and never re-fetchable; rejection states scope/policy cause safely.
- **Technical/localization/source:** principal/app/tenant IDs and safe credential ID/version only. Desktop detail sections; narrow full drawer; EN/AR and bidi-safe credentials. Source `identity/foundation.controller.ts`, `foundation.service.ts`, credential/auth guard and BFF action route. No OIC-7. Acceptance: browser never receives stored secret except explicit one-time issue response; API authorization independently enforced.
